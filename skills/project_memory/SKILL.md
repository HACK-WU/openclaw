# 项目级记忆系统（Project Memory System）

一套经过验证的、适用于 AI Agent 场景的项目级记忆架构。核心目标是让 Agent 能**跨会话**记住项目知识，持久化在项目目录中。

## 核心设计原则

以下原则是整个记忆系统的基石，适用于任何项目：

### 1. 记忆跟随项目，而非跟随 Agent

记忆文件存储在**项目目录**下（如 `.project-memory/`），与代码同仓库。Agent 来来去去，但项目知识永存。

    {projectDir}/
    ├── .project-memory/        # 记忆目录
    │   ├── MEMORY.md           # 永久记忆（核心知识）
    │   └── SESSION.md          # 会话记忆（当前工作进展）
    ├── src/
    └── ...

**好处**：

- 记忆可以通过 Git 版本控制
- 换 Agent、换机器不丢失知识
- 团队成员可共享项目记忆

### 2. 分层记忆架构

记忆分为两层，各司其职：

| 层级         | 文件         | 特点               | 典型内容                               |
| ------------ | ------------ | ------------------ | -------------------------------------- |
| **永久记忆** | `MEMORY.md`  | 长期、精炼、跨会话 | 架构决策、编码约定、踩坑记录、项目结构 |
| **会话记忆** | `SESSION.md` | 当前会话、临时     | 当前任务、工作进展、待确认事项         |

**设计思路**：

- 永久记忆是"项目百科"——经过提炼的核心知识，跨会话保留
- 会话记忆是"白板"——当前在做什么、做到哪了，会话结束可清理

### 3. Agent 自主判断记忆内容

不要由系统决定"什么该记"。Agent 自己最清楚在工作中发现了什么重要信息。

**应该记录的**（给 Agent 的指引）：

- ✅ 项目的 bug 或奇怪行为（如 "Prisma SQLite 下不支持 enum"）
- ✅ 架构决策和技术选型变化
- ✅ 某个方案被否决及其原因
- ✅ 关键代码路径和模块职责
- ✅ 编码约定或团队规范
- ✅ 用户的偏好和习惯

**不应该记录的**：

- ❌ 常规操作（如运行命令、读文件）
- ❌ 中间调试步骤
- ❌ 显而易见的信息（README 已说明的）

### 4. 惰性去重

Agent 在写入记忆前，先读取文件现有内容以避免明显重复。但**不需要**花额外精力做精确去重——少量重复远比丢信息好。

**关键细节**：如果新记忆比已有记忆更详细（例如记录了具体的环境变量名，而已有记忆只说了"通过环境变量注入"），保留更详细的版本，删除粗略版本。

**为什么**：

- 过度去重浪费 token 且可能丢信息
- 少量重复无害
- 简单的"写前先读"足够了

### 5. 降频注入节省 Token

不是每次交互都把全部记忆内容塞进上下文。采用**降频注入**策略：

| 内容         | 首次交互 | 后续交互           |
| ------------ | -------- | ------------------ |
| 记忆文件路径 | ✅ 注入  | ✅ 每次注入        |
| 记忆文件内容 | ✅ 注入  | 🔄 每 N 次注入一次 |
| 记忆管理规则 | ✅ 注入  | 🔄 每 N 次注入一次 |

**为什么**：

- Agent 在首次交互时已学会规则
- 路径每次提供，Agent 需要时可自行读取最新内容
- 大幅减少 token 消耗，同时不影响 Agent 工作

### 6. 简短精炼原则

所有记忆内容必须保持**高度概括**。每条记忆用一两句话概括关键信息。

**好的记忆条目**：

- "JWT 认证，token 24h，refresh token 7d"
- "认证逻辑在 src/auth/jwt.ts，中间件在 src/middleware/auth.ts"
- "Prisma findMany 的 skip 不支持超过 100000"

**不好的记忆条目**：

- 大段代码
- 详细的调试过程
- 完整的 API 文档

## 记忆文件模板

### 永久记忆 (`MEMORY.md`)

```markdown
# Project Memory

## 架构决策

- （技术选型、架构模式、关键决策及其原因）

## 代码结构

- （核心模块路径、架构分层、重要文件职责）

## 编码约定

- （命名规范、代码风格、团队约定）

## 踩坑记录

- （已知 bug、奇怪行为、环境限制）

## 项目知识

- （技术栈、依赖关系、部署配置）

## 用户偏好

- （用户的习惯、偏好设置、工作风格）
```

### 会话记忆 (`SESSION.md`)

```markdown
# Session Notes

## 当前任务

- （正在实现的功能）

## 进展

- （各部分的进度）

## 待确认

- （需要决策的问题）

## 未完成

- （已知但尚未开始的工作）
```

## 生命周期管理

### 文件创建时机

| 文件         | 创建时机           | 初始内容 |
| ------------ | ------------------ | -------- |
| `MEMORY.md`  | 项目首次启用记忆时 | 空模板   |
| `SESSION.md` | 会话开始时         | 空模板   |

### 文件清理策略

| 文件         | 清理时机             | 处理方式                               |
| ------------ | -------------------- | -------------------------------------- |
| `MEMORY.md`  | 长期保留，不轻易清理 | 定期精简过时内容即可                   |
| `SESSION.md` | 会话/任务结束时      | 有价值的信息提炼到 MEMORY.md，然后清空 |

### 记忆继承

当新的工作环境创建时，如果已存在 `MEMORY.md`，新会话可直接复用。这样 Agent 从一开始就能获得之前积累的项目知识。

## 实现检查清单

在任何项目中实现此记忆系统时，确认以下要点：

- [ ] 确定记忆目录位置（建议：`{projectDir}/.project-memory/`）
- [ ] 准备记忆文件模板（MEMORY.md + SESSION.md）
- [ ] 设计提示词注入策略（降频参数 N 的取值）
- [ ] 实现文件初始化逻辑（首次启动时创建目录和模板文件）
- [ ] 实现上下文注入逻辑（区分首次 / 降频 / 普通轮次）
- [ ] 设计清理策略（会话结束时 SESSION → MEMORY 的提炼流程）
- [ ] 配置 `.gitignore`（建议提交 `MEMORY.md`，忽略 `SESSION.md`）
- [ ] 设置大小上限和预警（建议总量 50KB 上限，80% 预警）

---

## 安全注意事项

1.  **大小控制**：设置记忆文件总大小上限，防止上下文过长
2.  **敏感信息**：提示 Agent 不要在记忆中存储密码、密钥等敏感信息
3.  **定期精简**：永久记忆会自然增长，建议定期审查并精简过时内容

## 适配不同项目的指引

| 项目类型                | 建议配置                                    |
| ----------------------- | ------------------------------------------- |
| **个人项目 / 单 Agent** | MEMORY.md + SESSION.md，直接读写            |
| **短期一次性任务**      | 只用 SESSION.md，任务结束后清理             |
| **长期维护项目**        | 完整模式 + Git 提交 MEMORY.md + 定期精简    |
| **团队共享知识库**      | MEMORY.md 提交到 Git，团队成员和 Agent 共享 |

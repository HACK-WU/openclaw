# 项目导出/导入统一设计

## 需求背景

当前已实现的文档导出/导入功能仅限于文档类型，而项目规则（rules）和技能（skills）也需要类似功能。用户希望在项目管理对话框中统一处理这三类资源的导出和导入。

## 当前实现状态

| 类型          | 导出                      | 导入                      | 状态   |
| ------------- | ------------------------- | ------------------------- | ------ |
| 文档 (docs)   | ✅ `projects.docs.export` | ✅ `projects.docs.import` | 已实现 |
| 规则 (rules)  | ❌                        | ❌                        | 未实现 |
| 技能 (skills) | ❌                        | ❌                        | 未实现 |

## 技术方案

### 文件格式

采用 ZIP 格式，内部结构如下：

```
project-export-{timestamp}.zip
├── manifest.json          # 导出清单，记录版本和资源列表
├── docs/
│   ├── {doc-id}.md
│   └── {doc-id}.json      # 元数据（名称、创建时间等）
├── rules/
│   ├── {rule-id}.md
│   └── {rule-id}.json
└── skills/
    ├── {skill-id}.md
    └── {skill-id}.json
```

#### manifest.json 示例

```json
{
  "version": "1.0",
  "exportedAt": 1713600000000,
  "projectId": "proj-xxx",
  "projectName": "bkmonitor",
  "resources": {
    "docs": [{ "id": "doc-1", "name": "项目规范.md", "createdAt": 1713500000000 }],
    "rules": [{ "id": "rule-1", "title": "编码规范", "createdAt": 1713400000000 }],
    "skills": [{ "id": "skill-1", "name": "数据查询", "createdAt": 1713300000000 }]
  },
  "stats": {
    "docs": 3,
    "rules": 2,
    "skills": 1,
    "total": 6
  }
}
```

### RPC API 设计

#### 导出

```typescript
// Request
{
  projectId: string;
  resourceTypes: ("docs" | "rules" | "skills")[];  // 必选，至少选一种
  docIds?: string[];    // 可选，不传则导出全部
  ruleIds?: string[];   // 可选
  skillIds?: string[];  // 可选
}

// Response
{
  filename: string;
  contentType: string;
  data: string;         // Base64 ZIP
  stats: {
    docs: number;
    rules: number;
    skills: number;
    total: number;
  };
  exportedAt: number;
}
```

#### 导入预览

```typescript
// Request
{
  projectId: string;
  data: string;         // Base64 ZIP
}

// Response
{
  stats: {
    docs: { total: number; new: number; conflict: number };
    rules: { total: number; new: number; conflict: number };
    skills: { total: number; new: number; conflict: number };
  };
  resources: {
    docs: ImportPreviewItem[];
    rules: ImportPreviewItem[];
    skills: ImportPreviewItem[];
  };
}

type ImportPreviewItem = {
  id: string;
  name: string;
  type: "doc" | "rule" | "skill";
  hasConflict: boolean;
  existingId?: string;
};
```

#### 导入

```typescript
// Request
{
  projectId: string;
  data: string;         // Base64 ZIP
  conflictStrategy: "rename" | "overwrite" | "skip";
  // 可选：只导入特定类型
  resourceTypes?: ("docs" | "rules" | "skills")[];
}

// Response
{
  imported: {
    docs: number;
    rules: number;
    skills: number;
  };
  skipped: {
    docs: number;
    rules: number;
    skills: number;
  };
  errors: Array<{
    type: "doc" | "rule" | "skill";
    name: string;
    reason: string;
  }>;
}
```

### 冲突处理逻辑

名称相同即视为冲突：

| 资源类型 | 冲突判断依据 |
| -------- | ------------ |
| 文档     | `doc.name`   |
| 规则     | `rule.title` |
| 技能     | `skill.name` |

策略：

- **重命名导入**：在名称后添加 `(导入)` 或 `(import)` 后缀
- **覆盖现有**：更新现有资源的 `content`，保留原 `id`
- **跳过冲突**：保留现有资源，跳过导入

## 替代方案对比

| 方案                                   | 优点                           | 缺点                   |
| -------------------------------------- | ------------------------------ | ---------------------- |
| **统一导出/导入（推荐）**              | 用户操作简便，一次处理多种资源 | 实现复杂度稍高         |
| 分别为 docs/rules/skills 实现导出/导入 | 与现有实现一致，代码重复       | 用户需多次操作，体验差 |

推荐采用**统一导出/导入方案**。
